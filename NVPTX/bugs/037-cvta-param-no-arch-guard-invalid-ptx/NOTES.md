# 037 — cvta.param / cvta.to.param TableGen patterns lack a subtarget predicate, emitting cvta.param on sub-sm_70 / sub-PTX-7.7 targets (and a nonexistent .u32 form)

- **Kind:** other (invalid PTX)
- **Reachable via:** default llc
- **Component:** NVPTXIntrinsics.td 2879-2900 (foreach at 2897-2900; NG_TO_G/G_TO_NG multiclasses at 2879-2895); selected in NVPTXISelDAGToDAG.cpp SelectAddrSpaceCast lines 968-970 and 999-1001  (round-6 area `W08-ld-st-intrinsics`)
- **Note:** "invalid PTX" entries are validated against the PTX ISA + strong in-tree corroboration (sibling guards / orderings); no local `ptxas` was available to execute the rejection.

## Summary

`cvta.param`/`cvta.to.param` patterns carry no subtarget predicate — emitted below sm_70/PTX7.7, and a nonexistent `cvta.param.u32` form on 32-bit

## Mechanism / root cause

The cvta address-space-cast instructions are generated by:

  foreach space = ["local", "shared", "global", "const", "param"] in {
    defm cvta_#space    : NG_TO_G<space>;   // default Supports32=1, Preds=[]
    defm cvta_to_#space : G_TO_NG<space>;   // default Supports32=1, Preds=[]
  }

NG_TO_G/G_TO_NG attach Requires<Preds> with Preds defaulting to []. For local/shared/global/const that is fine (cvta on those spaces is old, PTX 2.0+). But 'param' is included in the same loop with the same empty predicate, so the cvta_param / cvta_to_param machine instructions (both the .u32 and .u64 forms) carry NO Requires<> guard. cvta.param / cvta.to.param require PTX ISA 7.7 and sm_70 — this is exactly the in-tree authority NVPTXSubtarget::hasCvtaParam() = (SmVersion>=70 && PTXVersion>=77), and the official test llvm/test/CodeGen/NVPTX/lower-args-gridconstant.ll compiles it only with -mcpu=sm_70 -mattr=+ptx77. NVPTXLowerArgs correctly gates its own cvta.param emission on hasCvtaParam(), but the raw instruction patterns are reachable from valid IR (an addrspacecast to/from the param address space AS 101, lowered in SelectAddrSpaceCast via NVPTX::cvta_param_64 / cvta_to_param_64 with no arch check), so llc happily emits cvta.param on any -mcpu. ptxas for sm_30/sm_50/sm_60 rejects cvta.param. Additionally, because Supports32=1, a 32-bit nvptx triple emits 'cvta.param.u32', a form that does not exist in PTX at all (cvta.param only has a .u64 form), so it is invalid even on sm_90/ptx80.

## Trigger

Compile valid IR containing an addrspacecast between the NVPTX param address space (AS 101) and generic, targeting any arch below sm_70 / PTX 7.7. E.g. `addrspacecast ptr addrspace(101) %p to ptr` (reverse direction `... to ptr addrspace(101)` selects cvta.to.param). Confirmed reachable via plain addrspacecast and via the auto-upgraded llvm.nvvm.ptr.param.to.gen / ptr.gen.to.param intrinsics.

## Reproducer

```
target triple = "nvptx64-nvidia-cuda"

define ptr @f(ptr addrspace(101) %p) {
  %g = addrspacecast ptr addrspace(101) %p to ptr
  ret ptr %g
}
```

Command: `llc -mtriple=nvptx -mcpu=sm_60 -o - repro.ll`
