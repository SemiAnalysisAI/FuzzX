# 039 — Formatted surface store sust.p with sub-32-bit type emits invalid PTX (sust.p.*.b8 / sust.p.*.b16)

- **Kind:** other (invalid PTX)
- **Reachable via:** default llc
- **Component:** NVPTXIntrinsics.td 4521-4522, 4544-4545, 4569-4570, 4668-4669, 4694-4695, 4719-4720, 4821-4822, 4846-4847, 4871-4872  (round-6 area `W04-tex-surf`)
- **Note:** "invalid PTX" entries are validated against the PTX ISA + strong in-tree corroboration (sibling guards / orderings); no local `ptxas` was available to execute the rejection.

## Summary

formatted surface store `sust.p` with i8/i16 value emits `sust.p.1d.b8`/`.b16` — the formatted store only has a `.b32` form in PTX

## Mechanism / root cause

The .td defines formatted-surface-store instructions whose mnemonic carries a sub-word data-type suffix, e.g.
  defm SUST_P_1D_I8_TRAP  : SUST_1D<"sust.p.1d.b8.trap",  B16>;   (line 4521)
  defm SUST_P_1D_I16_TRAP : SUST_1D<"sust.p.1d.b16.trap", B16>;   (line 4522)
and the v2/v4 and 2d/3d analogues. Each carries a real DAG pattern selecting the matching int_nvvm_sust_p_*_{i8,i16,v2i8,...}_trap intrinsic (generated by SurfaceStoreIntrinsics in IntrinsicsNVVM.td line 2333-2364 for TV_I8/TV_I16 vecs). The PTX ISA (sect. 9.7.12.2, Surface Instructions: sust) defines the FORMATTED store with a fixed .b32 data type only:
  sust.p.{1d,2d,3d}.vec.b32.clamp [a, b], c;   // formatted
The .ctype = {.b8,.b16,.b32,.b64} set applies ONLY to the unformatted form (sust.b). There is no sust.p.*.b8 or sust.p.*.b16 in PTX. So for the i8/i16 (and v2/v4 of those) formatted-store intrinsics the backend emits a mnemonic that does not exist in the ISA. LLVM's own test generator acknowledges this: llvm/test/CodeGen/NVPTX/surf-tex.py line 380-381 skips fmt=='p' && ctype!='b32', and line 948 carries the comment "FIXME: spec does not list any sust.p variants other than b32" before listing exactly these sust.p.*.b8/.b16 mnemonics. (Note: the SUST_P array variants at lines 4593+,4745+ are NOT reachable because the corresponding int_nvvm_sust_p_a1d/a2d intrinsics are not defined — llc reports them as unknown intrinsics — so only the 1d/2d/3d non-array subword forms are a live bug.)

## Trigger

Valid IR calling a formatted-surface-store intrinsic with an i8/i16 value, e.g. llvm.nvvm.sust.p.1d.i8.trap, llvm.nvvm.sust.p.2d.i16.trap, llvm.nvvm.sust.p.1d.v2i8.trap, llvm.nvvm.sust.p.3d.v4i8.trap. Emitted at the default target (sm_75) and any sm_XX; no flags needed. ptxas would reject the resulting sust.p.1d.b8.trap / sust.p.2d.b16.trap mnemonics since the formatted store only accepts .b32.

## Reproducer

```
target triple = "nvptx64-nvidia-cuda"
declare void @llvm.nvvm.sust.p.1d.i8.trap(i64, i32, i16)
declare void @llvm.nvvm.sust.p.2d.i16.trap(i64, i32, i32, i16)
define ptx_kernel void @t_p_1d_i8(i64 %s, i32 %x, i16 %v) {
  tail call void @llvm.nvvm.sust.p.1d.i8.trap(i64 %s, i32 %x, i16 %v)
  ret void
}
define ptx_kernel void @t_p_2d_i16(i64 %s, i32 %x, i32 %y, i16 %v) {
  tail call void @llvm.nvvm.sust.p.2d.i16.trap(i64 %s, i32 %x, i32 %y, i16 %v)
  ret void
}
```

Command: `llc -mtriple=nvptx64-nvidia-cuda -o - repro.ll`
